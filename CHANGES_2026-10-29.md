# 2026-10-29 - pack format v2, faster bulk loading, worker pools

Install order matters:
1. Put the files of amibroker-web-engine-update.zip into your amibroker-web-engine project and let Render deploy. The app now reads
   pack v1 AND v2 blocks, so nothing changes yet.
2. Put convert.py of nse-data-engine-update.zip into nse-data-engine/backend/ and run "Convert DB to Parquet & Upload R2" by hand
   (workflow_dispatch). The history packs are rebuilt once in v2 (the pack format is part of the fingerprint); the recent pack too.
   Do NOT do step 2 before step 1: an old app cannot read v2 blocks.
3. Open /bulk-test.html on the phone (stocks = 1000) and press 1, 1 again, 2 and 3.

Changed: js/pack-codec.js, js/range-engine.js, js/config.js (APP_BUILD only), package.json
New: js/range-plan.js, js/worker-core.js, js/data-worker.js, js/worker-pool.js, js/compute-pool.js, js/bench-task.js, bulk-test.html,
tests/pack-v2-test.mjs, tests/browser/{_serve.mjs,bulk-harness.html,bulk-load.mjs,fflate-load.mjs,compute-pool.mjs,bulk-page.mjs},
tests/fixtures/{pack-v2.json,fake-r2/}
Not changed: app.js (it already clears the chart when a symbol has no data: this.display([])), everything else.
Tests: npm test (old + pack-v2) and npm run test:browser (needs Chromium + playwright).

Update after the first phone test (same day): the worker pool waited only 6 s for its workers to start and then decoded in the page
for good - on a slow network the first start takes longer. Now: 30 s, and the workers are started while the data downloads.
bulk-test.html now picks an even spread of active stocks (not the longest histories), rewrites ONE progress line, and shows the
download time and decode time separately.

## Added later the same day: Scan, Explore and Backtest on GitHub (and the runner repo)
Run on GitHub now has five buttons: Send Scan / Explore / Backtest / Optimize / Walk-Forward. The normal buttons of the Analysis window are
unchanged and still run on the phone; if GitHub gives any trouble the message says so and you just press the normal button.
- Scan and Explore: the symbols are shared over the machines (at most one machine per 100 symbols). Backtest: one machine.
- The result screens are the same code as on the phone (checked: the screens from GitHub and from the phone are identical).
Install order:  1) this zip into amibroker-web-engine (Render deploys it; the runner reads its js/ folder from the same repo),
                2) amibroker-analysis-runner-update.zip into the runner repo (replace the same files),
                3) only then the data update (convert.py).
New / changed here: js/analysis.js, js/analysis-core.js (explore split in two halves), js/remote-analysis.js, js/json-nan.js,
tests/browser/{analysis-harness.html,github-modes.mjs}

Results stay in the runner repo (jobs/<id>/result.json) for ALL five job types. New button in Run on GitHub: "Load jobs from the repo" rebuilds the
list from that folder (done automatically when the list is empty), so another phone, or a cleared browser, can open every past result
without a new analysis. Use the same repo name and token on the other device. (js/remote-analysis.js; checked in tests/browser/github-modes.mjs)

## Fix: an Explore result would not open ("View result" did nothing)
Cause: an Explore over many symbols (746 here, weekly, from 2000) made a result file with far too many rows for a phone to download and open.
Now: the runner stores Scan / Explore / Backtest results compressed (about 10 times smaller) and keeps the first 20,000 rows of an Explore in the
order your formula sorts them (the summary rows still count ALL rows; the Info tab says how many rows there were). The app opens both the new
and the old results (an old big Explore result is cut to its first 20,000 rows when opened, so the one you already have should open now),
and "View result" shows "Loading..." and, if something goes wrong, the reason in the panel instead of nothing.
Files: js/remote-analysis.js, js/json-nan.js, js/analysis.js (app); src/jobs.mjs, src/nf.mjs (runner).
Install: app files first, then the runner files (same order as before).
